FINQA MLOPS GETTING STARTED
===========================
0. DATA SETUP:
--------------
1. Download the raw FinQA repository ZIP:
   "https://github.com/czyssrs/FinQA/archive/refs/heads/main.zip"
2. Extract the archive and ensure the "FinQA-main" directory containing "dataset/" (with train.json, dev.json, test.json) is located in the repository root.

1. ENVIRONMENT SETUP:
---------------------
Create environment:  python3 -m venv .venv
Activate:            source .venv/bin/activate
Dependencies:        .venv/bin/pip install -r requirements.txt
Ollama Model Pull:   ollama pull llama3.2:3b-instruct-q4_K_M
Ollama Model Build:  ollama create finqa-llama3.2 -f config/Modelfile
AWS configuration:   aws configure  # Required if deploying to SageMaker or querying the cloud endpoint

2. PIPELINE STRUCTURE:
----------------------
scripts/preprocess.py       -> Cleans raw datasets; shrinks file sizes by ~54% and outputs to data/.
scripts/prepare_mlx_data.py -> Creates MLX training dataset splits with retriever-aligned gold contexts.
scripts/train.sh            -> Prepares data, executes QLoRA fine-tuning, and runs adapter generation.
src/client.py               -> Handles model inference routing (Ollama, MLX-LM, SageMaker) and records metrics.
src/retriever.py            -> Hybrid FAISS (dense) + BM25 (sparse) retriever with Header-Aware Table Chunking.
src/evaluator.py            -> Evaluates program tokens, execution value, and symbolic equation equality.
evaluation/run_baseline_eval.py -> Evaluates batch program execution accuracy.
evaluation/generate_rgb.py      -> Generates the 4 RAG RGB testbed datasets (noise, negative rejection, integration, counterfactuals).
evaluation/run_rgb_eval.py      -> Evaluates a specific model (e.g. baseline or tuned) against the RGB testbeds.
evaluation/run_benchmarks.py    -> Unified comparative evaluation sweeps (runs standard and RGB testbeds across active backends).
cloud/deploy.py             -> Packages model and deploys real-time AWS SageMaker GPU endpoint.
cloud/cleanup.py            -> Tears down active SageMaker endpoints, configs, and registered model models.
scripts/query.py            -> Test-runs retrieval & generation on a single index.


3. COMMONLY USED COMMANDS:
--------------------------
Install Dependencies:   .venv/bin/pip install -r requirements.txt
Build Ollama Model:     ollama create finqa-llama3.2 -f config/Modelfile
Preprocess Datasets:    .venv/bin/python scripts/preprocess.py
Prepare MLX Dataset:    .venv/bin/python scripts/prepare_mlx_data.py
Run Full Train Cycle:   ./scripts/train.sh
Fuse Model:             .venv/bin/python -m mlx_lm.fuse --model mlx-community/Llama-3.2-3B-Instruct-4bit --adapter-path ./adapters --save-path ./fused_model
Serve Tuned Model:      .venv/bin/python -m mlx_lm.server --model ./fused_model --port 11435
Compile RGB Testbeds:   .venv/bin/python evaluation/generate_rgb.py
Run Tuned Gold Eval:    .venv/bin/python evaluation/run_baseline_eval.py --model finqa-llama3.2-tuned --mode gold_chunks --limit 3 --show-comparison
Run Batch RAG Eval:     .venv/bin/python evaluation/run_baseline_eval.py --mode retrieved --limit 3 --show-comparison
Run RGB Eval Sweep:     .venv/bin/python evaluation/run_rgb_eval.py --model finqa-llama3.2-tuned
Deploy to SageMaker:    .venv/bin/python cloud/deploy.py --bucket <S3_BUCKET_NAME> --role <IAM_ROLE_ARN> --instance-type ml.g4dn.xlarge
Deploy via S3 Override: .venv/bin/python cloud/deploy.py --bucket <S3_BUCKET_NAME> --role <IAM_ROLE_ARN> --s3-uri s3://<S3_BUCKET_NAME>/finqa-llama3.2-tuned/model.tar.gz --instance-type ml.g4dn.xlarge
Run Benchmarks Harness: .venv/bin/python evaluation/run_benchmarks.py --limit 20 --rgb-limit 50
Tear Down SageMaker:    .venv/bin/python cloud/cleanup.py
Run Single Query:       .venv/bin/python scripts/query.py --index 0


4. DATASET INTEGRITY NOTES:
---------------------------
- Train / Val / Test splits have 0% data leakage (no shared IDs).
- Public test.json and private_test.json share 726 overlapping examples.


5. MLX TO OLLAMA BRIDGE NOTES (OR SERVING TUNED MODELS VIA MLX):
----------------------------------------------------------------
- MLX requires standard Hugging Face model formats (Safetensors) to train.
- Ollama requires the GGUF model format to run local inference.
- Fusing and converting 4-bit models directly to GGUF using MLX is not supported due to MLX layout bugs.
- Therefore, we serve our tuned model using MLX's high-performance native OpenAI-compatible server:
  1. Train adapter using mlx_lm.lora.
  2. Fuse the adapter:
     .venv/bin/python -m mlx_lm.fuse --model mlx-community/Llama-3.2-3B-Instruct-4bit --adapter-path ./adapters --save-path ./fused_model
  3. Start the MLX-LM local server on port 11435:
     .venv/bin/python -m mlx_lm.server --model ./fused_model --port 11435
  4. Query model using OllamaClient with model name "finqa-llama3.2-tuned". The client dynamically routes the request to the MLX-LM server at port 11435.


6. REPOSITORY HYGIENE:
----------------------
- A .gitignore file is placed in the root directory.
- It ensures local virtual environments (.venv/), compiled python caches (__pycache__/), system files (.DS_Store), and large model artifacts (adapters/, fused_model/) are kept out of Git.
